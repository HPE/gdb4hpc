Adding Tests to the lgdb_test suite:


STEP 1:
Add your source file(s) to a current directory or a new directory inside lgdb_test_harness.

Current source files are located in the current directories named as follows:
bd_dt/c  	: basic debugging/data type tests for c
bd_dt/C++	: basic_debugging/data type tests for C++
bd_dt/fortran   : basic debugging/data type tests for fortran
open_acc        : open_acc tests
upc             : upc tests


Note that you can create a new directory from the lgdb_test_harness directory
and add tests therein. Do not place tests directly inside lgdb_test_harness parent directory.
They must be in a subdirectory. This tool will dynamically locate all source file directories.

Required files for a given test:
1. Source file.
2. .rc file, contained within are the lgdb commands.

   Do not use the batch command in lgdb's launch command.  Aesop builds batch
   scripts dynamically for you.

3. testname.txt master output file which contains all of the expected output commands from lgdb.
   This file is used to compare against actual test output to determine Pass/Fail states. This file must be generated by
   running lgdb manually or running this test harness which will create the .out file.  View the .out file for correctness.
   If it correct for all commands, mv testname.out testname.txt. Note that the first time you run, not having a .txt file
   no Pass/Fail status or .rep report will be generated.

   NOTE: The .txt file name must have the same name as the test .out file.



STEP 2:
There are 4 test suites for lgdb

	1. sanity_list 
	2. basic_list
	3. full_list
	4. gpu_list


Open the list to which you want to add your test.
This file contains a table:

testname                |location               |run_command
c_assert_wodecomp       |bd_dt/c                |c_assert_wodecomp.rc --output=c_assert_wodecomp.out
c_assert_wdecomp        |bd_dt/c                |c_assert_wdecomp.rc --output=c_assert_wdecomp.out
c_assign                |bd_dt/c                |c_assign.rc --output=c_assign.out
c_breakpoint            |bd_dt/c                |c_breakpoint.rc --output=c_breakpoint.out

Field 1 - testname - name of the executable
Field 2 - Location - directory in which the tests are located
Field 3 - lgdb run command which includes the output file designation. Do not specify directory in which its located.
          This is done in the locatio field.


Note: All fields are required.

Note: When comparing the tests output (.out) with the master output file (.txt), the tool expects the filenames to be the same.
      e.g. Master .txt file = test1.txt, thus the output file must be test1.out. 

      Ensure the output file designation in the test suite list (basic_list,
      sanity_list, full_list, gpu_list) in the run_command field, 
      is the same as the associated master.txt file.



STEP 3: 
Add the commands to compile the test to the build_src file.

Field 1 - Location - directory in which the tests are located
Field 2 - source_files - a tab delimeted list - listing all executables which are run in the .rc file for this test.
Field 3 - Options - compile options

Field 4 - executable file name - ALL executable file names MUST post-pend with .x
Field 5 - Link? - If field is 'N', then the source files in Field 2 will be compiled seperately and exectuables for each
          are saved as the filenames specified in the executable_files field.
		  e.g. c_type_test.c will be compiled and the associated executable will be named c_type_test.x
		       c_cmp_diff.c will be compiled and the associated executable will be named c_cmp_test.x

          If Link field is 'Y', then the source files in Field 2 will be compiled, linked and an exectuable will be created
          as the filename specified in the executable_files field.
		  e.g. wtime.c and mtest.c will be compiled, linked and the associated executable will be named c_test7.x

	  Note: Associated .h files MUST be located in the lgdb_test_harness/include directory.

Note: All fields are required.
